# VibeOS Demo

VibeOS Demo is a local Node.js service and browser shell that demonstrates UI generated by an LLM at runtime. Each app window is a sandboxed iframe with its own session. Click, submit, Enter, and form-change events return to the service, which asks the model for the next HTML document and structured application state.

The project is a UI and session experiment. It does not read local files, run shell commands, access browser data, or provide a real operating system.

## How it works

```text
Node.js service
    ↓
Windows 11 style desktop shell
    ↓
Window manager and sandboxed app iframes
    ↓
iframe event bridge
    ↓
POST /api/sessions/:id/event
    ↓
LLM returns HTML and JSON state
    ↓
Replace iframe srcdoc and save state in the session
```

The bundled desktop contains Browser, Terminal, Calculator, Files, Text Editor, Tasks, Settings, Vibe Prompt, and About windows. New temporary apps can be requested from the desktop input.

## Requirements and start-up

Use Windows 10 or 11, Node.js 20 or newer, and Chrome or Edge. Check Node with `node -v`.

The default `.env.example` uses `LLM_PROVIDER=mock`, so the shell can start without a network call or API key. On Windows:

```powershell
Copy-Item .env.example .env
.\start.ps1
```

You can also run `start.cmd` from Command Prompt or start the service directly:

```powershell
node src/server.js
```

Open `http://127.0.0.1:8765` after the service reports that it is listening. `.\restart.ps1` wraps stop and start, and `.\stop.ps1` stops the process that owns port 8765. Pressing `Ctrl+C` in the server terminal is the least invasive way to stop it. To stop a listener directly, run:

```powershell
Get-NetTCPConnection -LocalPort 8765 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

## Configure a model

Copy `.env.example` to `.env` and choose a provider. The service accepts `mock`, `openai`, and `anthropic`.

For OpenAI or an OpenAI-compatible endpoint:

```env
LLM_PROVIDER=openai
OPENAI_API_KEY=your-key
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4.1-mini
LLM_THINKING_LEVEL=off
```

For Anthropic:

```env
LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=your-key
ANTHROPIC_BASE_URL=https://api.anthropic.com
ANTHROPIC_MODEL=claude-3-5-sonnet-latest
LLM_THINKING_LEVEL=off
```

`LLM_THINKING_LEVEL` accepts `off`, `low`, `medium`, `high`, and `max`. Higher levels allow more reasoning before the UI is generated and usually take more time and tokens. The configured timeout is 45 seconds by default. Keep API keys in `.env`, which is ignored by Git.

The LLM response is expected to be a JSON object containing the next UI document and its state. OpenAI-compatible calls use `/v1/chat/completions` with `response_format: { "type": "json_object" }` when the endpoint supports it. The service still prompts the model for JSON when an endpoint does not implement that option.

## Use the demo

Click an app in the Dock or open the app grid from **Activities**. Describe a new app in the desktop input when needed. After a real provider is configured, each event continues the same session, so the generated UI and application state accumulate within that window.

## Project files and logs

```text
vibeos-demo/
  .env.example           provider and runtime template
  start.ps1 / start.cmd  Windows start commands
  stop.ps1                stop the process using port 8765
  restart.ps1             stop and start wrapper
  src/server.js           HTTP server, providers, sessions, and state
  src/model-output.js     JSON extraction and response validation
  src/vibe-runtime.js     generated-app runtime helpers
  src/logger.js           NDJSON logging and rotation
  public/index.html       desktop shell markup
  public/styles.css       desktop and window styles
  public/app.js            window manager and iframe bridge
```

Runtime logs are written to `logs/vibeos-YYYYMMDD.ndjson`. They record service events, HTTP timing, LLM calls, iframe events, and session lifecycle. Files older than seven days are removed by the logger.

## Safety boundary

The default configuration keeps `VIBEOS_ALLOW_LOCAL_TOOLS=false`. The service removes returned `<script>` elements and inline event handlers, and app windows use the iframe `sandbox` attribute. The demo does not access the real filesystem, execute PowerShell, CMD, Bash, or other system commands, or read browser history, cookies, passwords, or credentials. Session state is held in server memory and is lost when the service restarts.

## API

`GET /api/config` returns the selected provider, model, and readiness state.

`POST /api/sessions` creates an app session. A minimal request is:

```json
{
  "appId": "custom",
  "title": "My App",
  "intent": "Create a kanban board"
}
```

`POST /api/sessions/:id/event` receives an iframe event. The frontend sends it automatically.

`GET /api/health` returns service health and the current session count.

## Troubleshooting

If the page opens but does not respond, confirm `LLM_PROVIDER`, the matching API key, base URL, and model in `.env`, then restart the service. The `mock` provider is useful for checking the shell and event bridge without an API call.

If an OpenAI-compatible endpoint rejects `response_format`, remove that field from the request in `src/server.js`; the prompt still asks for a JSON object. The service does not run local commands because generated HTML is the subject of this demo and command execution would add a separate permission boundary.

## Limits

- The shell is not a real operating system and has no kernel, driver, or persistent filesystem layer.
- App state lives in memory and disappears after a restart.
- Small models may return invalid JSON or rough layouts even when the service is healthy.
- The iframe sandbox and HTML cleaning reduce risk but do not make the service suitable for untrusted public users.
